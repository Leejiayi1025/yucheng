# 语程 · 邮箱验证码配置 & 部署指南

> 目标：让用户注册时**真的收到验证码邮件**，并把 App 部署到公网让手机能访问。

> **当前线上并非本文描述的「一台服务器同时跑前后端」**，而是
> 前端 Netlify、后端+数据库 Railway 分开部署 —— 那套流程见 [部署指南.md](部署指南.md)。
> 本文保留两类内容：**邮箱配置的细节**，以及**自建服务器（VPS + Nginx + pm2）这条备选路线**。

---

## 一、先配邮箱

验证码要通过邮件发给用户。程序里是**两级回落**：

| 优先级 | 方式 | 什么时候用 |
|---|---|---|
| 1 | **Resend API**（`MAIL_API_URL` + `MAIL_API_KEY`） | 线上推荐。只要一个 Key，不用自己搭 SMTP |
| 2 | **SMTP**（QQ / 163 邮箱授权码） | 本地开发，或 Resend 没配时的回退 |
| 3 | 都没配 | 不会静默失败：验证码打到服务端日志，并由接口回传给前端，方便联调 |

配好之后打开 `http://你的后端/api/auth/mail-status`，返回的 `mode` 是 `api` / `smtp` / `none`，
一眼看出走的哪条通道。

### 方式 A：Resend API（线上推荐）

1. 到 [resend.com](https://resend.com) 注册，在 **API Keys** 里创建一个 Key（形如 `re_xxx`）
2. 后端 `.env` 里填：
   ```ini
   MAIL_API_URL=https://api.resend.com/emails
   MAIL_API_KEY=re_你的Key
   MAIL_FROM=语程 <no-reply@你的域名>
   ```
   > 自有域名 `yuchengailee.online` 已在 Resend 完成域名验证，`MAIL_FROM` 可直接用：
   > `MAIL_FROM=语程 <no-reply@yuchengailee.online>`（审核通过前才先填 `onboarding@resend.dev` 临时调试）
3. 重启后端，用上面的 `mail-status` 确认 `mode` 是 `api`

### 方式 B：QQ 邮箱 SMTP（本地开发用，5 分钟搞定，完全免费）

**第 1 步：拿到「授权码」**

1. 电脑打开 [mail.qq.com](https://mail.qq.com) 登录你的 QQ 邮箱
2. 点顶部 **设置 → 账号**（或「账户」）
3. 往下找到 **「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务」**
4. 把 **「IMAP/SMTP服务」** 打开 → 按提示用手机发一条短信验证
5. 验证后会弹出一串 **16 位授权码**（形如 `abcdwxyzefghijkl`）→ **复制保存**

> ⚠️ 这个授权码**只会显示一次**，且**不是你的 QQ 密码**。

**第 2 步：填进后端配置**

打开 `D:\语程\后端\.env`，加上这几行（把中文替换成你的）：

```ini
MAIL_SMTP_HOST=smtp.qq.com
MAIL_SMTP_PORT=465
MAIL_SMTP_USER=你的QQ号@qq.com
MAIL_SMTP_PASS=刚才那串16位授权码
MAIL_FROM=语程 <你的QQ号@qq.com>
```

> `MAIL_FROM` 里的发件邮箱**必须和 `MAIL_SMTP_USER` 一致**，否则 QQ 服务器会拒发。

**第 3 步：重启后端并自检**

```bash
# 重启后端后，浏览器访问：
http://你的地址:4000/api/auth/mail-status
```

看到这样就成了：

```json
{ "mode": "smtp", "ok": true, "hint": "已配置 SMTP，验证码会真实发到用户邮箱" }
```

**第 4 步：实测**

在 App 注册页输入你自己的邮箱 → 点「获取验证码」→ 去邮箱收信（**记得翻垃圾箱**）。

---

### 方式 B：163 邮箱 SMTP

和上面完全一样，只是 host 换成 `smtp.163.com`。授权码在 163 邮箱的 **设置 → POP3/SMTP/IMAP** 里开启获取。

---

### 方式 C：专业邮件服务（量大时再考虑）

如果要发几千封/月，用 Resend / Brevo 这类服务，它们在 `后端/.env` 里这样配：

```ini
MAIL_API_URL=https://api.resend.com/emails
MAIL_API_KEY=你的key
MAIL_FROM=语程 <no-reply@你的域名.com>
```

> 这类服务需要**自己的域名**做发件人验证（要在 DNS 加几条记录），所以建议先用 QQ 邮箱跑通流程。

---

### 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 打开「IMAP/SMTP服务」时提示要发短信 | 正常流程，用绑定的手机号发即可 |
| 服务端报 `Invalid login` | 用了 QQ **登录密码**而不是**授权码** ✗ |
| 服务端报 `550 From address...` | `MAIL_FROM` 和 `MAIL_SMTP_USER` 不一致 ✗ |
| 用户说收不到 | 大概率在**垃圾箱**；也可能是对方邮箱把 QQ 来信拦了 |
| 一天发不出去 | 个人邮箱有频率限制（QQ 约 50 封/天），小规模够用 |

## 二、部署 App

### 结构说明

你的项目是**后端托管前端**的架构：

```
前端源码  D:\语程\frontend\app        → 构建成 D:\语程\frontend\app\dist（静态文件）
后端      D:\语程\后端                → Express，同时托管 dist 和提供 /api
```

所以**只需要部署一个后端**，它会把前端页面一起 serve 出去，天然同源、没有跨域问题。

> ⚠️ 路径注意：目录名是英文 `frontend`，不是「前端」。
> 历史上 `.gitignore` 里写过中文的「前端/dist/」，正因为对不上实际路径，
> 构建产物才被误提交进仓库。

> ⚠️ 如果改成**前后端分域部署**（比如前端放 Netlify、后端放 Railway），
> 就不再是同源了，必须把前端域名加进后端的 `CORS_ORIGINS` 环境变量，
> 否则浏览器会把所有请求拦下来。线上默认已内置 `https://yuchengailee.online` 与 `https://yuchengaileen.netlify.app`。

---

### 方案一：云服务器（正式运营，推荐）

**1. 买服务器**

- 腾讯云 / 阿里云「轻量应用服务器」，2核2G 就够
- 系统选 **Ubuntu 22.04** 或 **Debian 12**
- 学生认证后大约 ¥10/月

**2. 装环境**（登录服务器后执行）

```bash
# Node 20
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# MySQL
sudo apt install -y mysql-server
sudo mysql -e "CREATE DATABASE yucheng CHARACTER SET utf8mb4;
               CREATE USER 'yc'@'localhost' IDENTIFIED BY '换成强密码';
               GRANT ALL ON yucheng.* TO 'yc'@'localhost';"

# pm2（让后端常驻、开机自启）
sudo npm i -g pm2

# Nginx（做反向代理 + HTTPS）
sudo apt install -y nginx
```

**3. 上传代码**

```bash
# 你本地构建前端产物
cd D:\语程\frontend\app
npm run build          # 产出 D:\语程\frontend\app\dist

# 把构建产物和后端整个目录上传到服务器（scp 或 git）
scp -r D:\语程\frontend\app\dist  user@服务器IP:/opt/yucheng/frontend-dist
scp -r D:\语程\后端               user@服务器IP:/opt/yucheng/backend
```

> 构建产物**不在 git 里**（`.gitignore` 已覆盖 `frontend/dist/` 与 `frontend/app/dist/`），
> 所以不能靠 `git clone` 把 dist 带到服务器，必须**在服务器上重新构建**，或者像上面这样单独 scp 过去。

**4. 配后端 `.env`**（在服务器上编辑 `/opt/yucheng/backend/.env`）

```ini
# 数据库
DB_HOST=127.0.0.1
DB_USER=yc
DB_PASSWORD=刚才设的强密码
DB_NAME=yucheng

# 登录令牌密钥（换成随机长串！）
JWT_SECRET=用 openssl rand -hex 32 生成一个

# DeepSeek（语音解析）。模型名只支持 deepseek-chat / deepseek-reasoner
DEEPSEEK_API_KEY=你的key
DEEPSEEK_MODEL=deepseek-chat

# 邮件（上面第一节配好的）—— Resend API 优先，未配时才走下面的 SMTP
MAIL_API_URL=https://api.resend.com/emails
MAIL_API_KEY=re_你的Key
MAIL_FROM=语程 <no-reply@你的域名>

# SMTP 回退通道（可选）
# MAIL_SMTP_HOST=smtp.qq.com
# MAIL_SMTP_PORT=465
# MAIL_SMTP_USER=你的QQ号@qq.com
# MAIL_SMTP_PASS=授权码

# 跨域白名单（可选）。前后端同域部署时不用填；
# 分域部署（前端在别的域名）时必须把前端域名加进来，否则请求会被浏览器拦下
# CORS_ORIGINS=https://你的前端域名
```

**5. 启动后端**

```bash
cd /opt/yucheng/backend
npm install
pm2 start src/index.js --name yucheng
pm2 save && pm2 startup     # 开机自启
```

**6. Nginx + HTTPS**

```nginx
# /etc/nginx/sites-available/yucheng
server {
    listen 80;
    server_name 你的域名.com;

    location / {
        proxy_pass http://127.0.0.1:4000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/yucheng /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# 免费 HTTPS 证书
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名.com      # 自动配好证书并续期
```

**7. 开放端口**

云服务器控制台的「安全组」放行 **80 / 443**（4000 不用对外开放，Nginx 内部转发）。

完成后手机浏览器访问 `https://你的域名.com` 即可，验证码也会真实发到用户邮箱。

> **注意**：用 HTTPS 后，手机的语音识别（`SpeechRecognition`）才能正常工作 —— 浏览器要求麦克风必须在安全上下文（https 或 localhost）下使用。

---

### 方案二：内网穿透（先验证功能，最省事）

不想买服务器时，用内网穿透把本机 4000 端口暴露到公网：

```bash
# 以 cpolar 为例（有免费版），或 ngrok / frp
cpolar http 4000
```

它会给你一个 `https://xxxx.cpolar.cn` 的地址 → 手机打开就能用，验证码同样能收到。

**缺点**：地址会变、速度慢、不适合正式运营，**只用来验证功能**。

## 四、验证码走不走邮件，怎么判断？

后端逻辑是「**配了就真发，没配就把验证码直接回给前端**」，方便开发阶段调试：

| 情况 | `/api/auth/send-code` 返回 | 用户看到 |
|---|---|---|
| 已配 SMTP/API | `{"ok":true,"emailed":true}` | 只提示「验证码已发送至 xxx」 |
| 未配 | `{"ok":true,"dev":true,"code":"123456"}` | 页面上直接显示「邮件服务未配置 · 验证码：123456」 |

所以**配好邮箱后，验证码就不会再出现在页面上了**，会自动变成真实发信 —— 你不需要改任何代码。
