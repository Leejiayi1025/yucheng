## 二、前端部署（Netlify）

### 配置参数
| 配置项 | 值 |
|---|---|
| 基础目录 Base directory | `frontend/app` |
| 构建命令 Build command | `npm run build` |
| 发布目录 Publish directory | `dist` |

### 部署流程
1. GitHub仓库推送到`master`分支
2. Netlify绑定仓库，按上表填写构建参数
3. 自动构建部署，得到`xxx.netlify.app`域名
4. 后续每次push代码自动触发重新部署
5. 当前线上主地址：**https://yuchengailee.online**（自定义域名，备用 https://yuchengaileen.netlify.app/）

### 自定义域名（已上线）
- 域名：`yuchengailee.online`（阿里云购买、已实名）
- 解析记录（阿里云 DNS，已生效）：
  | 记录类型 | 主机记录 | 记录值 |
  |---|---|---|
  | A | `@` | `75.2.60.5`（Netlify 负载均衡） |
  | CNAME | `www` | `yuchengaileen.netlify.app` |
- 在 Netlify → Domain settings 里添加自定义域名，自动校验 DNS 并签发 HTTPS 证书（Let's Encrypt 自动续期）
- `@` 和 `www` 两个入口都能访问，Netlify 默认 301 跳转统一到主域名

## 三、后端+数据库部署（Railway）

### 服务配置
| 配置项 | 值 |
|---|---|
| 根目录 Root Directory | `后端` |
| 构建命令 | `npm install` |
| 启动命令 Start Command | `node src/index.js` |

### 环境变量清单
| 变量名 | 说明 | 获取方式 |
|---|---|---|
| `PORT` | 服务端口，Railway自动注入 | 自动 |
| `DB_HOST`/`DB_USER`/`DB_PASSWORD`/`DB_NAME` | MySQL连接参数 | 添加MySQL服务后自动注入 |
| `JWT_SECRET` | JWT登录密钥 | 自定义随机长字符串。**必须设置**，缺失时鉴权会失效 |
| `MAIL_API_URL` | 邮件服务API地址 | `https://api.resend.com/emails` |
| `MAIL_API_KEY` | 邮件服务API密钥 | Resend后台获取 |
| `MAIL_FROM` | 发件人地址 | `语程 <onboarding@resend.dev>`（域名审核通过后换成自有域名） |
| `DEEPSEEK_API_KEY` | AI日程解析密钥 | DeepSeek开放平台获取 |
| `DEEPSEEK_MODEL` | 解析用的模型 | 可选，默认 `deepseek-chat`（另一个是 `deepseek-reasoner`） |
| `CORS_ORIGINS` | 跨域白名单，逗号分隔 | 可选。线上前端域名与本地端口已内置默认值（含 `https://yuchengailee.online` 与 `https://yuchengaileen.netlify.app`）；换域名时在这里追加 |

> 部署完可以访问 `https://你的后端域名/api/auth/mail-status` 自检邮件通道，
> 返回的 `mode` 是 `api` / `smtp` / `none`。
>
> 另外：`frontend/dist` 与 `frontend/app/dist` 已经**不在 git 里**了。
> 如果 Railway 的服务依赖仓库里现成的 dist，需要确认它自己会跑构建 ——
> 更推荐的做法是前端交给 Netlify 构建发布。

### 数据库初始化
1. 执行`数据库/schema-full.sql`创建全部表结构
2. 创建管理员账号，设置`role='admin'`
3. 服务启动时自动检查表结构，无需手动运行初始化脚本

> ⚠️ **themes 表注意**（2026-10-07 修复）：`preview_card / preview_text / preview_primary`
> 列宽必须为 `varchar(100)`。若线上库是旧版 `varchar(20)`，长值（rgba / 渐变）会被静默截断，
> 需执行：
> ```sql
> ALTER TABLE themes MODIFY `preview_card` varchar(100) DEFAULT NULL,
>                     MODIFY `preview_text` varchar(100) DEFAULT NULL,
>                     MODIFY `preview_primary` varchar(100) DEFAULT NULL;
> UPDATE themes SET preview_card='rgba(28, 28, 30, 0.85)' WHERE id=15;  -- ios
> UPDATE themes SET preview_card='rgba(30, 41, 59, 0.78)' WHERE id=14;  -- midnight
> UPDATE themes SET preview_card='linear-gradient(145deg, #222222 0%, #161616 100%)' WHERE id=20;  -- black-gold
> ```

### 管理后台
部署完成后访问 `https://你的后端域名/admin.html`，使用管理员账号登录，查看数据指标。

## 四、本地/局域网测试配置

### 启动步骤
1. **启动后端**：
   ```bash
   cd 后端
   # 配置本地.env数据库连接参数
   node src/index.js
   ```
   后端默认运行在 `http://localhost:4000`

2. **启动前端开发服务**：
   ```bash
   cd frontend/app
   npm run dev
   ```
   前端开发服务默认运行在 `http://localhost:5173`

3. **局域网手机访问**：
   - 手机和电脑连接同一个WiFi
   - 查看电脑局域网IP（如`192.168.0.101`）
   - 手机访问 `http://电脑IP:4000` 即可使用打包后的完整版本
   - 注意：HTTP局域网环境下Web Speech语音识别不可用，会弹出浏览器打开提示，属于正常内测限制

## 五、邮件服务配置（Resend，替代旧QQ邮箱SMTP）

### 配置流程
1. 注册Resend账号：https://resend.com/
2. 后台获取API Key，填入环境变量`MAIL_API_KEY`，并配置`MAIL_API_URL=https://api.resend.com/emails`
3. 内测阶段可直接使用默认测试发件域名`resend.dev`，发件人填`onboarding@resend.dev`
4. 正式上线可添加自有域名，按提示配置DNS解析，使用自有域名发件
5. 无需SMTP服务器、授权码，直接通过API发送邮件，配置简单、送达率高

### 邮件模板
- 注册/找回密码验证码邮件
- 发件人显示名称：语程
- 邮件内展示6位数字验证码，10分钟有效

## 常见问题
1. **Netlify额度用完**：可更换账号，或临时使用本地局域网测试
2. **非浏览器环境语音用不了**：内测阶段Web Speech API仅支持HTTPS浏览器/localhost，属于浏览器能力限制，弹窗提示复制链接到浏览器打开即可
3. **局域网收不到验证码**：本地后端配置好Resend API Key即可正常发邮件，和网络环境无关
